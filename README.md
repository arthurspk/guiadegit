## :dart: O guia para alavancar a sua carreira

> Git é o sistema de controle de versão distribuído mais usado do mundo, criado por Linus Torvalds em 2005 para o desenvolvimento do próprio kernel Linux. Ele roda 100% local, sem depender de servidor, registra o histórico completo do seu código e permite trabalhar em branches paralelas sem medo de quebrar nada — é a base de praticamente todo fluxo de trabalho em equipe, do GitHub ao GitLab, do Bitbucket ao Azure DevOps. Este guia reúne documentação oficial, cursos gratuitos e pagos, livros, canais, ferramentas, os principais fluxos de trabalho (Git Flow, GitHub Flow, trunk-based) e um capítulo dedicado a usar IA na prática com Git — tudo verificado e organizado para quem está dando o primeiro `git init` e para quem já vive de rebase interativo no dia a dia.

## 🤖 IA na prática

Git ganhou um papel novo na era dos agentes de IA: cada agente (Copilot, Cursor, Claude Code) trabalha em cima do histórico e das branches do seu repositório, então dominar Git de verdade é o que te dá controle sobre o que a IA muda no seu código.

**Mensagens de commit com IA**
- Ferramentas como [OpenCommit](https://github.com/di-sukharev/opencommit) e [aicommits](https://github.com/Nutlope/aicommits) leem o `git diff` que está em stage e geram uma mensagem de commit no padrão Conventional Commits em segundos — rode `git add` normalmente e deixe a IA escrever o `git commit -m`.
- Ambas funcionam com múltiplos provedores (OpenAI, Claude, modelos locais via Ollama); revise sempre a mensagem gerada antes de confirmar, principalmente o tipo (`feat`, `fix`, `refactor`) e o escopo.
- Sem instalar nada: peça para o [GitHub Copilot](https://github.com/features/copilot) ou para o [Claude Code](https://code.claude.com/docs/en/overview) "escreva uma mensagem de commit para este diff seguindo Conventional Commits" — ambos leem o `git diff` do seu editor ou terminal.

**Resolução de conflitos assistida**
- No GitHub, o Copilot pode analisar um conflito de merge em um pull request e propor a resolução automaticamente, como documentado em [Resolvendo um conflito de merge no GitHub](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/addressing-merge-conflicts/resolving-a-merge-conflict-on-github).
- O [Cursor](https://docs.cursor.com/pt-BR/more/ai-merge-conflicts) entende os dois lados de um conflito e sugere uma resolução direto no editor, com um botão de resolução assistida na própria UI de conflito.
- Com Git puro: rode `git diff` no arquivo em conflito, cole o trecho entre `<<<<<<<` e `>>>>>>>` para o assistente e peça para explicar a intenção de cada lado antes de aceitar qualquer resolução automática — a IA erra menos quando você dá contexto do que cada branch estava tentando fazer.

**Limites e boas práticas**
- IA sugere resolução de conflito, mas não sabe qual branch está "certa" em uma decisão de produto — sempre confira com quem escreveu cada lado do conflito antes de aceitar.
- Nunca aceite um `git commit --amend` ou `git push --force` sugerido por um agente sem entender o efeito no histórico compartilhado; reescrever histórico já publicado quebra o trabalho de quem mais está no repositório.
- Mensagens de commit geradas por IA tendem a descrever "o quê" mudou olhando só o diff, não "por quê" — complete manualmente o motivo da mudança quando não for óbvio.
- Revise o `git log --oneline` depois de qualquer sessão longa com um agente de IA: é comum acumular commits redundantes que valem um `git rebase -i` antes do push.

- [Certificação GitHub Foundations gratuita (artigo, DIO)](https://www.dio.me/articles/certificacao-github-foundations-100-gratuita) — Passo a passo gratuito de como se preparar e obter a certificação GitHub Foundations.

## 💼 Carreira e vagas

Git e GitHub são pré-requisito silencioso em praticamente toda vaga técnica no Brasil — raramente aparecem como tópico isolado no anúncio, mas dominar branch, rebase e um pull request bem feito é o que diferencia quem passa no teste técnico.
- [2025 Stack Overflow Developer Survey](https://survey.stackoverflow.co/2025/) — Git segue como a ferramenta de controle de versão mais usada por desenvolvedores no mundo todo.
- [Programathor](https://programathor.com.br/) — Vagas de tecnologia no Brasil, com filtro por stack e senioridade.
- [GeekHunter](https://www.geekhunter.com.br/) — Plataforma brasileira onde empresas fazem propostas a devs.
- [Coodesh](https://coodesh.com/) — Vagas tech no Brasil com processos seletivos padronizados, geralmente incluindo teste prático em repositório Git.
- [Remotar](https://remotar.com.br/) — Vagas 100% remotas para brasileiros.
- [Tech Interview Handbook](https://www.techinterviewhandbook.org/) — Preparação para entrevistas técnicas, incluindo perguntas comuns sobre fluxo de trabalho com Git.
